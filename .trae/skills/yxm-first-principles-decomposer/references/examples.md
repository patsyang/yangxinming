# 第一性原理案例：Artem 的世界

## 案例 1：TeddySnaps 照片系统

### 表层问题

“我们需要给家长发送更多照片。”

### 被挑战的假设

1. ❌ 家长想要更多照片 → 实际上：他们想要正确的照片。
2. ❌ 所有时刻都同样重要 → 实际上：包含他们孩子的时刻才重要。
3. ❌ 员工应该负责筛选 → 实际上：员工时间昂贵，且执行不稳定。

### 基本真相

- 家长想要证明自己的孩子安全/开心。
- 脸 = 身份 = “那是我的孩子”。
- 时间 = 上下文 = “这是今天发生的”。
- 为了稳定性，自动 > 手动。

### 重建方案

AI 人脸识别 + 自动标注 + 面向家长的专属 feed。
员工自由拍照 → 系统自动分类并投递。

## 案例 2：TISA 招生流程

### 表层问题

“我们的招生流程太慢。”

### 被挑战的假设

1. ❌ 我们需要一开始拿到所有信息 → 实际上：我们只需要足以做决定的信息。
2. ❌ 表单必须完整 → 实际上：表单会制造摩擦。
3. ❌ 家长想提供信息 → 实际上：家长想收到确认。

### 基本真相

- 招生 = 承诺交换（家长承诺孩子，学校承诺名额）。
- 最小可行信息：孩子姓名、年龄、家长联系方式。
- 其他信息可以稍后补。
- 响应速度 = 质量感知。

### 重建方案

阶段 1：姓名 + 年龄 + email（30 秒）→ 立即预留名额。
阶段 2：详细表单（承诺之后）。
结果：速度快 10 倍，转化更高。

## 案例 3：GolfTab 点餐

### 表层问题

“高尔夫球手需要在球场上点餐。”

### 被挑战的假设

1. ❌ 需要完整餐厅菜单 → 实际上：简化菜单更好。
2. ❌ 需要精确送达时间 → 实际上：“第 X 洞前送到”就够了。
3. ❌ 需要复杂支付流程 → 实际上：记到房账/tab，之后结算。

### 基本真相

- 高尔夫球手的手经常脏或戴着手套。
- 球场上的注意力很有限。
- 位置 = 洞号（通过 tee time 已知）。
- 速度 > 选项数量。

### 重建方案

5 次点击点餐：商品 → 数量 → 洞号 → 确认 → 完成。
不浏览长菜单，不处理支付摩擦，不填地址。

## 案例 4：员工排班（TeddyKids）

### 表层问题

“员工排班复杂且耗时。”

### 被挑战的假设

1. ❌ 经理必须创建排班 → 实际上：AI 可以生成草稿，经理审批。
2. ❌ 员工偏好不可预测 → 实际上：模式会随时间浮现。
3. ❌ 师生比合规需要手工处理 → 实际上：这是纯数学问题。

### 基本真相

- 儿童:员工比例由法律强制规定（确定性）。
- 员工可用性存在模式（可学习）。
- 成本优化是数学问题。
- 人类监督只需要处理例外。

### 重建方案

算法生成排班 → 经理审查例外 → 员工确认。
80% 自动化，20% 人类判断。
