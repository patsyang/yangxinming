# 综合思维框架

## 组合方法：第一性原理 + Design Thinking + Systems Engineering

深度解决问题时，组合三个互补框架：

---

## 1. 第一性原理（Musk 方法）

**核心问题**：什么是基本为真的？

### 流程

1. 识别假设。
2. 拆到原子真相。
3. 从基本事实重建。

### 最适合

- 挑战常识和行业惯例。
- 找到非显而易见的方案。
- 降低成本 / 提升效率。

---

## 2. Stanford Design Thinking（IDEO 方法）

**核心问题**：人真正需要什么？

### 五个阶段

1. **共情**：深度理解用户需求、痛点和语境。
2. **定义**：框定真实问题（往往不同于用户口头描述的问题）。
3. **构思**：不急着判断，先生成大量方案。
4. **原型**：构建快速、低成本版本来测试。
5. **测试**：从真实用户反馈中学习并迭代。

### 关键实践

- **Beginner's Mind**：不带预设进入问题。
- **How Might We**：把问题重构成机会。
- **Rapid Prototyping**：快速学习，低成本失败。
- **User-Centered**：始终回到用户需求。

### 最适合

- 面向用户的产品。
- 创新和新概念。
- 理解未满足需求。

---

## 3. MIT Systems Engineering

**核心问题**：各部分如何相互作用？

### 系统思维原则

1. **整体视角**：系统行为来自部分之间的互动。
2. **反馈回路**：输出会影响输入（正反馈/负反馈）。
3. **边界**：定义系统与环境。
4. **层级**：系统包含子系统。
5. **涌现**：整体大于部分之和。

### 分析框架

```
输入 → 过程 → 输出 → 反馈
       ↑              ↓
       ←──────────────←
```

### 关键问题

- 系统边界在哪里？
- 反馈回路在哪里？
- 杠杆点在哪里？
- 可能有哪些非预期后果？

### 最适合

- 复杂多组件问题。
- 长期战略思考。
- 避免非预期后果。

---

## 综合方法

按顺序使用三个框架：

```
阶段 1：第一性原理
“这个问题中什么是基本为真的？”
→ 剥掉假设，找到原子真相

阶段 2：Design Thinking
“用户真正需要什么？”
→ 共情，定义真实问题，构思方案

阶段 3：Systems Engineering
“这个方案会如何与环境互动？”
→ 映射反馈回路，识别杠杆点，预测后果
```

## 何时使用哪个框架

| 情境 | 主框架 | 辅助框架 |
| --- | --- | --- |
| 挑战行业惯例 | 第一性原理 | Design Thinking |
| 新产品/新功能 | Design Thinking | Systems |
| 复杂组织问题 | Systems | 第一性原理 |
| 优化任务 | 第一性原理 | Systems |
| 创新 sprint | Design Thinking | 第一性原理 |

## 组合输出格式

```markdown
## 第一性原理分析
**被挑战的假设：**
- [假设] → [基本真相]

## Design Thinking 综合
**用户需求：**[他们真正需要什么]
**How Might We：**[重构后的问题]
**方案概念：**[前三个想法]

## 系统视角
**关键反馈回路：**
- [回路 1]
- [回路 2]

**杠杆点：**
- [小变化能带来大影响的位置]

**潜在非预期后果：**
- [需要监控的二阶影响]
```

## 与其他 skill 的整合

这个组合框架可以输入到：

- **inversion-strategist**：反转系统视角，寻找失败模式。
- **second-order-consequences**：映射方案的涟漪效应。
- **pre-mortem-analyst**：实施前做压力测试。
