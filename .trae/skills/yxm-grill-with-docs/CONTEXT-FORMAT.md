# CONTEXT.md 格式

## 结构

```md
# {上下文名称}

{一到两句话说明这个上下文是什么，以及为什么存在。}

## 语言

**订单**:
{一到两句话定义这个术语}
_避免_: 购买、交易

**发票**:
交付后发送给客户的付款请求。
_避免_: 账单、付款申请

**客户**:
下达订单的个人或组织。
_避免_: 客户端、买方、账号
```

## 规则

- **明确取舍。** 当同一个概念有多个说法时，选择一个最佳术语，并把其他说法列在 `_避免_` 下。
- **定义要紧。** 每个定义最多一到两句话。定义它是什么，不解释它怎么做。
- **只收录本项目上下文特有的术语。** 通用编程概念不应进入 `CONTEXT.md`，即使项目大量使用这些概念。新增术语前先判断：这是本上下文独有概念，还是通用概念？只保留前者。
- **自然分组。** 当术语出现自然簇时，可以用小标题分组；如果都属于同一主题，保持扁平列表即可。

## 单上下文与多上下文仓库

**单上下文（多数任务）:** 在当前任务目录放一个 `CONTEXT.md`，例如 `output/grill-with-doc/<task-slug>/CONTEXT.md`。

**多上下文:** 在当前任务目录放一个 `CONTEXT-MAP.md`，列出所有上下文的位置和关系：

```md
# 上下文地图

## 上下文

- [订单](./src/ordering/CONTEXT.md) - 接收并跟踪客户订单
- [计费](./src/billing/CONTEXT.md) - 生成发票并处理付款
- [履约](./src/fulfillment/CONTEXT.md) - 管理仓库拣货和发货

## 关系

- **订单 -> 履约**: 订单上下文发出 `OrderPlaced` 事件；履约上下文消费该事件并开始拣货
- **履约 -> 计费**: 履约上下文发出 `ShipmentDispatched` 事件；计费上下文消费该事件并生成发票
- **订单 <-> 计费**: 共享 `CustomerId` 和 `Money` 类型
```

本 skill 会自动判断使用哪种结构：

- 如果当前任务目录存在 `CONTEXT-MAP.md`，读取它来定位上下文
- 如果当前任务目录只有 `CONTEXT.md`，按单上下文处理
- 如果二者都不存在，在第一个术语被确认时再创建当前任务目录的 `CONTEXT.md`

当存在多个上下文时，先判断当前主题属于哪个上下文；如果不清楚，再提问确认。
