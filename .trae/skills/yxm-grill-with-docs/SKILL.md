持续追问方案的每个方面，直到形成共同理解。沿着设计树的每个分支推进，逐一解决决策之间的依赖关系。每个问题都必须给出你的推荐答案。

一次只问一个问题，并在继续之前等待用户对当前问题的反馈。

如果某个问题可以通过探索代码库回答，就优先探索代码库，而不是询问用户。

## 领域意识

探索代码库时，也要查找已有文档：

### 输出语言

所有对用户可见的输出和由本 skill 生成或维护的文档内容必须使用中文，包括追问、推荐答案、`CONTEXT.md`、`CONTEXT-MAP.md` 和 ADR 正文。保留必要的英文技术标识，例如文件名、命令、路径、API、schema 字段、代码符号、产品缩写和原文引用。

### 文件结构

所有输出都位于 `output/grill-with-doc/<task-slug>/` 下。每个会话 / 任务必须使用自己的子目录，不能直接写入 `output/grill-with-doc/` 根目录，也不能复用其他任务的 `CONTEXT.md` 或 ADR。

`<task-slug>` 用当前讨论主题生成，优先使用用户明确给出的产品、模块、方案或问题名；如果无法稳定命名，先问一个问题确认目录名。目录名使用小写英文、数字和连字符，例如 `udsp-product-concepts`、`config-publishing`。

多数任务只有一个上下文：

```
output/grill-with-doc/<task-slug>/
├── CONTEXT.md
└── adr/
    ├── 0001-event-sourced-orders.md
    └── 0002-postgres-for-write-model.md
```

如果当前任务目录存在 `CONTEXT-MAP.md`，说明该任务有多个上下文。该 map 指向每个上下文的位置：

```
output/grill-with-doc/<task-slug>/
├── CONTEXT-MAP.md
└── contexts/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── adr/
    │       └── 0001-<decision-name>.md
    └── billing/
        ├── CONTEXT.md
        └── adr/
            └── 0001-<decision-name>.md
```

延迟创建文件：只有确实有内容要写时才创建。如果不存在 `CONTEXT.md`，在第一个术语被确认时创建。如果不存在 `adr/`，在第一个 ADR 真正需要时创建。

根目录下已有的 `CONTEXT.md`、`adr/` 或其他文件只能视为历史产物。除非用户明确指定，否则新任务不得读取它们作为当前上下文，也不得继续向其中写入。

继续已有任务时，先定位对应 `output/grill-with-doc/<task-slug>/`。如果有多个可能目录，提出一个带推荐答案的问题确认，不要猜测写入目标。

## 会话过程中

### 用词表挑战表达

当用户使用的术语与 `CONTEXT.md` 中已有语言冲突时，立即指出。例如：“词表里把‘取消’定义为 X，但你现在似乎在表达 Y；到底是哪一个？”

### 收紧模糊语言

当用户使用模糊或多义词时，提出一个精确的标准术语。例如：“你说的是‘账号’，这里指客户还是用户？这两个对象不同。”

### 讨论具体场景

讨论领域关系时，用具体场景压测。主动构造能触及边界情况的场景，迫使概念边界变得精确。

### 严禁概念过度膨胀

不要为了显得严谨而发明新概念；新概念必须能改变判断、边界或行动，否则退回已有术语和具体场景。

### 与代码交叉验证

当用户描述某件事如何工作时，检查代码是否一致。如果发现矛盾，要指出来。例如：“代码里取消的是整个订单，但你刚才说可以部分取消；以哪个为准？”

### 即时更新 CONTEXT.md

当一个术语被确认时，立即更新当前任务目录内的 `CONTEXT.md`。不要攒到最后批量处理。格式遵循 [CONTEXT-FORMAT.md](./CONTEXT-FORMAT.md)。

`CONTEXT.md` 不能包含实现细节。不要把 `CONTEXT.md` 当成规格说明、草稿纸或实现决策库。它只是词表。

中文 `CONTEXT.md` 条目使用 `_避免_`，不要使用 `_Avoid_`。

### 谨慎创建 ADR

只有同时满足以下三个条件时，才建议创建 ADR：

1. **难以逆转**：未来改变主意的成本有实际意义
2. **缺少上下文会显得意外**：未来读者会疑惑“为什么要这么做”
3. **存在真实取舍**：确实有替代方案，并且因为具体理由选择了其中一个

如果缺少任一条件，就跳过 ADR。格式遵循 [ADR-FORMAT.md](./ADR-FORMAT.md)。
