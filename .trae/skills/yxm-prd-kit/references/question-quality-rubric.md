# Question Quality Rubric

每轮可以生成多个候选问题，但默认只问用户一个。问题必须帮助 PRD 变得更准确，而不是增加讨论负担。

## 必须满足

- 影响 PRD 事实、范围、对象、流程、状态、验收标准、排除项或风险依赖。
- 回答后能写入明确章节或账本。
- 不回答会导致误设计、返工、测试不可验或评审无法解释。
- 用户可以用有限信息回答。

## 评分

每个候选问题按 1-5 分评分。

```text
impact: 不回答会造成多大 PRD 错误
uncertainty: 当前证据缺口有多大
irreversibility: 后续修正成本有多高
dependency: 是否阻塞下一阶段
user_effort: 用户回答成本是否可接受，分数越高表示越容易回答
```

优先选择总分最高的问题。若两个问题分数接近，优先选择更早阶段、更难返工的问题。

## 不该问的问题

- “还有什么补充吗？”这类无方向开放问题。
- 与当前阶段无关的问题。
- 用户已经明确回答、否定或纠正过的问题。
- 只是为了显得严谨的问题。
- 可以安全假设且对后续影响低的问题。

## 合格问题格式

```text
我需要先确认一个会影响 <章节/对象/流程/验收> 的点：<问题>。

必要性：<为什么这个问题会影响 PRD，不确认会误设计什么>。

模拟场景：<一个贴近当前业务的具体例子，必须包含具体对象、用户动作、系统动作和前后状态变化，说明这个问题什么时候会发生>。

建议口径：建议采用 <推荐口径>。如果没有疑义，回复“接受”即可。

确认后我会把它回灌到 <回灌位置>。
```

模拟场景只给 1 个，必须使用当前 PRD 已出现的业务对象或流程，并包含具体对象、用户动作、系统动作和前后状态变化；不得为了举例扩展新需求，不得把未确认的场景当成 PRD 事实写入。

建议口径默认只给 1 个推荐方案。只有两个方案都合理且会明显影响 PRD 边界时，才使用 A/B 格式：

```text
建议口径：
- A. <推荐方案>（推荐）：<为什么更适合当前 PRD>
- B. <备选方案>：<什么情况下才选它>

如果没有疑义，回复“接受”表示采用 A；如选择 B，请回复“选 B”。
```

不得为了显得全面硬凑 B 方案；不得输出 3 个或更多选项。

如果不需要打扰用户，使用假设格式：

```text
我先按低风险假设推进：<假设>。
这个假设只影响 <影响范围>，后续如果你否定，我会回退到 <阶段> 修正。
```
