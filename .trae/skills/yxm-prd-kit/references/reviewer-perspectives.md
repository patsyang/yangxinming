# Reviewer Perspectives

Perspective Rotation Loop 防止问题集中在单一角色或同一类问法。每个计入 quota 的问题必须声明一个 perspective。

## 默认视角

| perspective | 关注点 |
| --- | --- |
| 客户一线使用者 | 日常工作怎么发生，入口、步骤、卡点和失败后怎么继续 |
| 客户安全/合规/管理者 | 结果是否可解释、可审计、能否支撑内部或外部合规 |
| 产品经理 | 价值、边界、MVP、优先级、是否过度设计 |
| CTO/架构负责人 | 对象、状态、依赖、数据来源、扩展性和实现边界 |
| 研发实现者 | 输入输出、状态迁移、异常、并发、异步和错误处理 |
| QA/测试 | 验收标准、边界条件、失败路径、可测性 |
| CEO/商业负责人 | 投入是否值得，是否有战略/商业闭环，是否值得首期做 |
| 交付/客户成功 | 部署、配置、解释、客户验收和交付材料是否可落地 |

## 使用规则

- 不允许连续多个阶段只从产品经理视角提问。
- 不允许同一类问题换话术计数。
- 当前阶段若存在用户、对象、状态、验收或业务结果不清，优先选择能暴露根因的视角。
