# 设计与执行计划

## 目的

`product-landscape-discovery` 是一个可复用 skill，用于最早期的产品探索阶段：用户有一个想法或问题领域，但还不知道竞品集合，需要在做定位、PRD、GTM 或投资决策前先找到外部参考。

这个 skill 优先优化发现广度，再做有证据支撑的收窄。它应避免过早锁定品类。

## 非目标

- 不为每个发现的公司产出完整公司 memo。
- 除非用户要求，否则不估算市场规模。
- 不假设最显眼的 SEO 榜单就是市场本身。
- 不强行把每个替代方案都塞进 SaaS 竞品桶。
- 不依赖付费 API 或某个特定垂直数据集。

## 设计原则

### 1. 从任务出发，而不是从品类出发

初始产品描述可能用了错误的品类名称。应从以下角度构建搜索种子：

- Job to be done。
- 痛点或风险。
- 用户角色或买方角色。
- 工作流对象。
- 既有工具链。
- 触发事件。
- 期望结果。

### 2. 广泛发现替代方案

竞品包括直接产品、相邻工具、服务、内部工作流、手工流程、开源项目、插件，以及平台原生功能。

### 3. 先证据，后综合

在写最终结论前，维护一个轻量 evidence ledger。每个高置信度判断都应能追溯到来源。

### 4. 针对搜索失败迭代

当搜索结果过宽、过窄、SEO 噪音过重或过旧时，调整术语、语言、来源类型和品类层级。

### 5. 以决策收束

最终交付物应帮助判断：下一步研究什么、忽略什么、向用户验证什么，以及哪些定位假设已经变得合理。

## 输入

最小输入：

- 一个产品想法、问题、目标用户或期望工作流。

可选输入：

- 地理范围。
- 行业。
- B2B/B2C/内部工具语境。
- 已知产品或公司。
- 研究用途：参考发现、PRD、定位、GTM、投资、roadmap。
- 期望深度：quick scan、standard landscape、deep report。
- 排除项。

## 深度模式

### 快速扫描（Quick Scan）

用于用户希望快速获得方向感的情况。

最低要求：

- 20 条有效证据。
- 8 个以上候选项。
- 5 个优先参考对象。
- 覆盖直接竞品、替代方案和 status quo 类型。
- 简短定位图。
- 3-5 个下一步验证问题。

### 标准版图（Standard Landscape）

产品规划的默认模式。

最低要求：

- 40 条有效证据。
- 15 个以上候选项。
- 8-12 个优先参考对象。
- 审视 direct、indirect、substitute、status quo、adjacent 和 inspiration-only。
- 输出证据表、功能矩阵、定位图、机会缺口。

### 深度报告（Deep Report）

用于用户正在准备重大投入、PRD、战略评审或 GTM 决策的情况。

最低要求：

- Standard landscape 的所有输出。
- 对每个优先参考对象做更深入画像。
- 在可获得时收集官方文档、定价、客户证明、评论、社区信号、发布历史、招聘/融资信号。
- 明确交接计划：公司深挖、用户访谈、定位或 PRD。

## 阶段计划

### 阶段 0：范围与假设

如果信息缺失，最多问三个问题。如果用户希望立即执行，就带着假设继续。

创建：

- 范围声明。
- 假设列表。
- 排除范围。
- 深度模式。

### 阶段 1：种子分类法

把输入转换成种子地图：

- `job_to_be_done`
- `problem_terms`
- `category_terms`
- `user_or_buyer_terms`
- `workflow_terms`
- `data_or_object_terms`
- `integration_terms`
- `outcome_terms`
- `negative_terms`

当品类不清楚时，创建多个品类假设。

### 阶段 2：广泛搜索

从所有主要查询族执行搜索：

- 品类发现。
- 竞品发现。
- 替代方案发现。
- 对比发现。
- 用户声音。
- 相邻生态。
- 新鲜度和活跃度检查。

记录：

- Query。
- 新来源。
- 新候选项。
- 新品类。
- 噪音模式。
- 后续 query。

### 阶段 3：证据台账（Evidence Ledger）

创建 evidence item，包含：

- 来源 URL。
- 来源类型。
- 候选项或品类。
- 事实。
- 推论。
- 置信度。
- 重要性。

产品事实优先使用官方来源；痛点信号使用社区/评论来源；发现线索使用对比/报告来源。

### 阶段 4：候选项归一化

去重并归一化：

- 公司 vs 产品。
- 旧名称 vs 新名称。
- 父平台 vs 功能。
- 开源项目 vs 商业产品。
- 服务公司 vs 产品化服务。

把每个候选项分类为 direct、indirect、substitute、status quo、adjacent 或 inspiration-only。

### 阶段 5：优先参考对象加深

按以下标准选择优先参考对象：

- 任务重合度。
- 用户重合度。
- 采用替代性。
- 证据强度。
- 产品参考价值。
- 新鲜度/活跃度。

对每个优先参考对象收集：

- 定位。
- 目标用户。
- 核心工作流。
- 关键能力。
- 定价或包装。
- 部署与集成。
- 客户或用户证明。
- 投诉或弱点信号。
- 应借鉴、避免和验证什么。

### 阶段 6：版图综合

构建三个视图：

- 基于类型的版图。
- 功能/工作流矩阵。
- 定位图。

定位图坐标轴应解释已发现的市场，例如：

- 工作流深度。
- 自动化水平。
- 客户规模。
- 部署复杂度。
- 技术集成负担。
- 价格/服务强度。
- 横向 vs 垂直聚焦。
- Point tool vs platform。

### 阶段 7：机会与风险

识别：

- 拥挤区域。
- 未被充分服务的任务。
- 现有玩家弱点。
- 强 status quo 阻力。
- 分发或信任约束。
- 差异化假设。
- 证据缺口。

### 阶段 8：下一步验证计划

以行动收尾：

- 哪 3-5 家公司需要 deep-dive。
- 需要做哪些用户访谈。
- 需要绘制哪些 status quo 工作流。
- 需要测试哪些定位假设。
- 下一步监控哪些来源。

## 失败模式与修复

| 失败 | 信号 | 修复 |
| --- | --- | --- |
| SEO 陷阱 | 结果都是没有一手证据的榜单文章 | 切到 docs、pricing、reviews、GitHub、forums、changelog |
| 品类锁定 | 所有结果都使用同一个品类短语 | 搜索任务、工作流、角色、结果和替代方案 |
| 大平台偏置 | 只出现大型供应商 | 加入 startup、open source、niche、alternative、for <persona> |
| 过宽 | 结果横跨无关产品 | 加入用户、工作流对象、行业、集成或 negative terms |
| 过窄 | 结果很少 | 使用英文、同义词、上位品类、相邻工作流 |
| 市场过旧 | 产品不活跃或文章陈旧 | 搜索当前 pricing、docs、changelog、active repos、recent reviews |
| 没有替代方案 | 只找到直接竞品 | 搜索 manual process、spreadsheet、template、consultant、internal tool |
| 置信度弱 | 单一来源主导判断 | 标记低置信度并寻找旁证 |

## 验收标准

一次完成的运行必须：

- 解释当前 workaround 或 status quo。
- 至少包含直接竞品、替代方案和 status quo 路径。
- 解释每个优先参考对象为什么重要。
- 为重要判断提供来源链接。
- 区分事实、推论和假设。
- 包含坐标轴有意义的定位图。
- 说明证据缺口和下一步验证动作。

## 交接指引

完成 landscape 后：

- 对优先公司使用公司研究 skill 做 deep-dive。
- 在参考集合和替代路径明确后使用定位工作流。
- 在目标用户、问题和差异化假设可信后使用 PRD 工作流。
- 仅在定位和目标细分更清楚后使用 GTM 工作流。
