# 证据与评分

## 证据条目（Evidence Item）

每条重要证据使用这个结构：

```json
{
  "evidence_id": "EV-001",
  "source_url": "",
  "source_type": "official_site|docs|pricing|review|community|comparison|news|job|github|analyst|other",
  "publish_or_access_date": "",
  "candidate_or_category": "",
  "fact": "",
  "inference": "",
  "confidence": "high|medium|low",
  "why_it_matters": ""
}
```

## 来源置信度

高置信度：

- 官方产品页。
- 产品文档。
- 定价页。
- 客户故事。
- 活跃的 GitHub repo、issue、release。
- 有清晰上下文的详细用户评论。

中置信度：

- 独立对比。
- 行业媒体。
- 招聘页面。
- 融资/新闻数据库。
- 有充分来源的 analyst 摘要。

低置信度：

- SEO 榜单文章。
- 无来源排名。
- 供应商自称市场领先。
- 没有新鲜度信号的旧文章。
- 没有上下文的匿名说法。

低置信度来源可以用来发现线索，但不应单独支撑强结论。

## 候选项评分

候选项按 0-5 分评分：

| 维度 | 含义 |
| --- | --- |
| 任务重合度 | 是否解决同一个核心任务 |
| 用户重合度 | 是否服务同一类用户、买方或操作员 |
| 替代性 | 是否可能被选择来替代目标产品 |
| 证据强度 | 是否由多个可信来源支撑 |
| 参考价值 | 是否有助于产品、工作流、UX、GTM 或商业模式学习 |
| 新鲜度 | 产品和证据是否仍然当前有效 |

分类指引：

- `direct_competitor`：任务重合度 >= 4，用户重合度 >= 4，替代性 >= 4。
- `indirect_competitor`：任务或用户重合度高，但入口点、买方或工作流不同。
- `substitute`：品类不同，但替代性 >= 3。
- `status_quo`：当前 workaround、手工流程、内部系统、服务或什么都不做。
- `adjacent_category`：上游、下游、平台、基础设施、插件、服务或开源生态。
- `inspiration_only`：有参考价值，但竞争关系弱。

## 证据强度

`strong`：

- 至少两个独立来源类型。
- 存在官方来源或用户/客户证明。
- 与任务和用户的相关性清楚。

`medium`：

- 存在基础来源。
- 竞争关系合理但尚未完全证明。
- 缺少定价、文档、评论或客户证明。

`weak`：

- 单一来源。
- 仅来自 SEO 的线索。
- 名称看起来相关，但任务/用户关系不清楚。

`reject`：

- 虽然关键词匹配，但实际无关。
- 不活跃或无法确认存在。
- 没有产品相关性的新闻/招聘噪音。

## 事实、推论、假设

区分：

- 事实：由来源直接支撑。
- 推论：由多个事实推出的合理结论。
- 假设：用于继续研究的临时假说。

把营销说法改写为归因说法。例如，写“该供应商将其定位为……”，而不是“它是领先的……”。
