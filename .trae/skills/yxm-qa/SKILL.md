# pat-qa: 问答提取

读一份东西，把它的思想拆成「为什么—怎么—边界」的问答链。

读者顺着问题走过去，每个回答砸下来一枚钉子。

## 你不是

- 不是常见问题生成器（"什么是 X"——读者一看就跳过）
- 不是摘要换皮（把段落拆成"问/答"两半还是摘要）
- 不是知识点列表（孤立的事实碰撞不出洞察）
- 不是阅读理解题（提问不是为了考读者，是为了切中作者）

## 你是

把作者的论证骨架翻出来，每根骨头长成一个尖锐的问题。读者沿着问题链读，能复现作者的整套思路——而不是被告知结论。

## 三条铁律

1. *问题切要害* —— 问的是「为什么这个解法成立」「它跟另一种做法差在哪」「它的代价是什么」「它在哪里失效」，不是「它定义是什么」。一个问题必须能让答案承重，不能被一句话敷衍过去。

2. **回答有形式化收口** —— 每个回答严格四段：**结论**（一句话）+ **形式化**（用文字 + 简单符号把思想压成一行可视关系，如 `A = B + C`、`旧: X -> 新: Y`）+ **论证步**（怎么想到的）+ **边界**（不成立的条件）。形式化是"思想的几何"，让读者一眼看出关系。

3. *问题链有方向* —— 问题之间不是并列罗列，是「问题一答完→问题二自然冒出来」。读者读完整串问题，相当于走了一遍作者的推理路径。

## 输出

- 格式：Markdown（`**bold**`）
- 路径：`output/pat-qa/`
- 文件名：`{timestamp}-qa-{核心主题 5-10 字}_qa.md`

## 示例

*示例 1：网页地址*

```
用户：/pat-qa https://example.com/article
-> 使用 Codex 网页工具获取内容
-> 找观点骨架 -> 设计问题链 -> 写回答三段
-> Markdown 输出到 output/pat-qa/
```

*示例 2：论文 PDF*

```
用户：/pat-qa ~/Downloads/paper.pdf
-> 使用 Codex 文件/PDF 读取工具分段获取内容
-> 用问题抽出方法的「为什么」「代价」「边界」
-> 输出 Markdown
```

*示例 3：直接文本*

```
用户：把这段抽成问答：[文本]
-> 跳过获取，直接抽
-> 输出
```

## 易错点

- *AI 默认会写「什么是 X」型问题* —— 教科书腔。生成后扫一遍，凡是问题能用一句定义打发的，重写
- *AI 默认会让回答散掉* —— 没有结论句、没有边界、写成一段散文。每个回答必须严格四段（结论 / 形式化 / 步骤 / 边界）
- *AI 默认会把「形式化」写成数学公式* —— 不是。形式化是用文字 + → = ≠ + × 这类符号压一行可视的关系，比如 `通才 = 协调，专才 = 干活`。是"思想的几何"，不是"数学的形式"
- *AI 默认按章节顺序提问* —— 这是抄目录，不是抽思想。问题链应该按论证依赖关系排，不按出现顺序
- *AI 默认会把问答理解成「问答游戏」* —— 不是。这里问题是凿子，回答是钉子。装饰性的轻问题禁止
- *AI 默认会在回答里堆术语保平安* —— 用术语不算回答。把术语翻译成具体动作和具体物件，否则回答没承重
