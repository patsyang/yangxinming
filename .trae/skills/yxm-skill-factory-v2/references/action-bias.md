# 行动类偏差库（bias-library: action）

`bias-libraries` 的注册实例——**行动/编排**类 skill 的偏差库。鲁班反向轴的源、判官攻行动类产物运行输出时的对照表。**单一事实源（行动类范围内）**——行动类的通用偏差唯一权威是本文件；鲁班图只**引用**它（标注"见 action-bias.md"，不复制内容），判官对照时通用偏差查这里、域偏差查鲁班图。一处源，不复制，不矛盾。

> 这是**行动类**的偏差库（注册约定、其他类型索引见 `bias-libraries.md`）。检查类库是 `failure-classes.md`，生成类库是 `generation-bias.md`。流程类（工作流/编排/决策）归入行动类——都是产出动作或状态变更。

## 它治什么病

行动类 skill 易出的偏差，判官可能把某一次具体执行毛病（如"重试导致重复发送"）当探针记下，造出的 skill 却还是漏这类。根因两层，这库治第二层：

- 第一层（断 channel）：判官只攻设计稿不攻产物运行输出——**重定向可解**，见各 persona。
- 第二层（偏差类型学缺失）：判官和鲁班的产出里没有"行动类偏差"这一维内容——**重定向补不回**。判官攻输出时手里只有零散探针，对没记过的偏差（如"幂等性缺失""错误传播断裂"）攻不到。这库补这一维。

判官有这库，攻行动类产物运行输出时**逐类对照**："我这里 N 类行动偏差，你的输出对每一类都处置了吗"——这是"靠记忆碰运气"换不来的系统性覆盖。

## 适用范围

本库服务**行动/编排**类 skill（执行动作、改状态、编排流程、自动化、决策落地）——价值在于"正确地把该做的事做了"。**检查/审计类、生成/创作类 skill 的偏差是另一套**（检查类见 `failure-classes.md`；生成类见 `generation-bias.md`），不套本库。

## 种子（行动类内域无关）

**只放换一个行动场景照样成立的通用偏差模式。** 不写某个具体系统/工具的特征（某 API 的限流、某平台的鉴权）——域特定偏差归鲁班当次的 per-mission 图，不进这里。这是这库不退化成"某次故障纪念碑"的全部支点。

每类 = 偏差名 + 它是什么 + 怎么落地为一个操作。措辞域中性：

- **未声明副作用** — 执行了未在契约里声明的副作用（多动了资源/发了通知/改了额外状态）。操作：列执行前后状态 diff，比对声明的输出集合，多出的=病。
- **不可逆操作无门控** — 没确认/没备份/没门控就执行不可逆动作（删除/发送/提交/覆盖）（**不可逆风险**，对应严重度殿）。操作：抽取不可逆动作，追"门控/确认/备份"在不在。
- **幂等性缺失** — 重试/重复触发导致重复生效（重复发通知/重复扣款/重复创建）。操作：追每步"重试会不会重复生效"，无幂等键=病。
- **错误传播断裂** — 子步骤失败未上报/未终止/未回滚，编排继续往下。操作：追每步失败分支"上报了吗/停了吗/回滚了吗"，断裂=病。
- **部分执行无回滚** — 失败时停在中间态，已改的状态无回滚。操作：追失败点"前面已改的状态回滚了吗"，无回滚=病。
- **顺序 / 依赖错排** — 步骤依赖错（B 依赖 A 却排在 A 前，或成环）。操作：画步骤依赖图，标记逆序/环。
- **状态不一致** — 编排中状态丢失/错位/脏读。操作：跨步骤追状态字段，比对预期流转 vs 实际。
- **边界条件未处理** — 空输入/极值/并发/超时未处理。操作：枚举边界（空/极大/极小/并发/超时），追每类的处置分支。
- **权限 / 范围越界** — 动了不该动的资源/超出声明范围。操作：比对声明范围 vs 实际触及资源集，越界=病。
- **输入校验缺失** — 未校验输入合法性（类型/权限/前置条件）就执行。操作：追执行前的校验步骤，缺失=病。
- **输出契约违约** — 实际输出形态/路径/格式/计数与契约声明不符。操作：比对声明输出 schema vs 实际产物。
- **可观测性缺失** — 执行不留可追溯日志/证据，失败无法定位。操作：追每步"留证据了吗"，无日志=病。

**绑定的是偏差模式，不是某次故障的具体值。** 某次具体的重复发送是"幂等性缺失"的实例，不是种子本身。种子换个行动场景照样成立。

## 生长（候选机制，非会话内自动写库）

种子是冷启动的底。库靠**运行反馈**长，但**不在会话内自动改本文件**——那会违反判官"只攻不修"的核心设定，也违反会话隔离（本文件是工厂自身契约，不该被某次会话改）。改用候选机制：

1. 判官攻产物运行输出时，发现一个**不属于已有任何一类**的新偏差。
2. 判官**记入当次会话的 `failure-candidates.md`**（只记录：新偏差模式 + 实例 + 为何不属于已有类）——判官只记录，不修库。
3. **会话结束后**，由**仓库维护者**审查 `failure-candidates.md`，决定哪些值得**抽象掉系统特征后沉淀**进本文件。
4. 沉淀是人工动作（更新本文件 + 版本号），不在任何会话的阶段里。

这是"可收敛的盲区"：判官和库都没记录过的偏差，**第一次会漏**；但漏过一次，它进候选、人沉淀后进库，**不再漏第二次**。人作为沉淀关卡，防"把系统特定误当通用类塞进来"。

## 防污染（承重，写死）

- **行动类库只收系统无关类。** 判官记的候选，若剥不掉系统特征，不沉淀进本文件——它归鲁班当次图。
- **不许把某次故障原样塞进来当"通用类"。** 某次具体的报错码、某条具体的失败日志，是实例不是类。塞实例 = 补丁 = 虚假完备感。
- 哪吒的守尖锐本能看见一长串就想瘦身——但这是价值验证骨，砍一项漏一类（见 `nezha.md`）。

## 它和鲁班图、判官、价值验证骨的关系（参照单一）

- **鲁班**画 per-mission 图时，先按 skill 类型选偏差库（选择见 `bias-libraries.md`），**行动类引用本文件**作为反向轴的底（标注"见 action-bias.md"，不复制内容），再推理域特定偏差轴。通用偏差是可迁移层，域轴是当次特化。
- **判官**（覆盖向四殿）攻运行输出时，逐类对照——通用偏差查本文件、域偏差查鲁班图。
- **价值验证骨**（`skill-anatomy.md`）行动类槽的"反向偏差子表"挂的就是本文件 + 鲁班域轴。
- **维护**：判官记候选（当次会话）；人沉淀（会话后，更新本文件）；鲁班引用 + 标域轴；哪吒不碰（承重清单）。

## 诚实的边界

- 库是 LLM 推理 + 运行反馈（经人沉淀）的产物，**不是真专家背书**。冷启动第一次会漏未知偏差。
- 它提高发现概率，**不保证发现**——判官和库都没记录过的全新偏差，首次仍有盲区。但保证漏过的不重漏（人沉淀后）。
- 因此收敛**不认"对任意输入有效"**，只认"可迁移偏差类已绑定 + 产物在锚定样本上被带证据演示执行过（spawn 运行）"。
