# 承重图谱

工厂有十来个机制，不是每个都同等承重。这份图谱用 **deletion test** 给每个机制定轻重：删了它，复杂度是**消失了**（那是 pass-through，可降级），还是在**多处重现**（那是承重，不许降级）。

用途：LLM 跑工厂时知道重兵压在哪；资源紧张时，机械机制可降级，承重机制不许动。这也是工厂「不自标深度」的落地——深度不从「机制多」长出来，从「哪些机制真承重」长出来。

## 标注原则

- **承重** = 删了它，病在多处重现。这是工厂立身的骨头，**不许降级**——无论主动还是 self-bootstrap 证伪后。承重机制跑不通 = `runtime_blocked`（红线 9），不是降级。区别于下面的"机械/可降级"：那些不触碰承重点（产物被运行 + 运行输出被攻），简化它们不会产出行尸；承重碰了就产行尸。
- **机械** = 服务于承重点的辅助步骤。重要，但可简化／降级，降级后承重点仍能成立（只是更费力／更糙）。
- **可降级** = 锦上添花。资源紧张时第一个砍，不影响工厂达成承重点。但「可降级」是初始假设，不是终身判决——有些原以为可降级的，被证伪后升为承重（如意象词库：历史反例证伪了「压缩工具可降级」）。证伪证据见下文 deletion test 理由。

## 承重（不许降级）

| 机制 | 为什么承重（deletion test） |
|------|---------------------------|
| **执行产物 + 攻运行输出** | 删了它，工厂退回「只审设计稿」——这正是工厂要治的行尸病，在所有产物上重现 |
| **诚实（宪法第四条）** | 删了任何一条，工厂的承诺全不可信（写下的话跑不起来），全局塌 |
| **偏差库对照表（按类型注册，见 `bias-libraries.md`）** | 删了它，判官对未记录的偏差攻不到（换地方看也看不出脑子里没有的），覆盖盲区在所有产物上重现 |
| **收敛关（含意外检验）** | 删了它，工厂无法区分「真收敛」和「走完流程」，假收敛在所有产物上重现 |
| **产物自验契约** | 删了它，产物的「净」无证据可查，行尸殿瞎攻，产物层的诚实无落地 |
| **红线集** | 删了它，死法没有下限锁，LLM 在每个死法上各栽一次 |
| **self-bootstrap 硬门** | 删了它，工厂自己从未被运行验证，所有机制都是纸面承诺 |
| **意象词库** | 双重身份：仍是压缩工具，但更是认知锚点。删了它，指令化退化——所有产物上重现（历史反例：全表格 + 编号红线，丢失「火种」式隐喻）。deletion test 证伪了「可降级」初始判断，承重的是「认知锚点」身份，不是「压缩工具」身份 |

## 机械（可简化／降级，但承重点仍成立）

| 机制 | 角色 | 降级后的形态 |
|------|------|-------------|
| **handoff 四件收尾** | 防随意停、可追溯 | 降为「更新 state + 留一行证据」，省略履职记录的细节 |
| **角色 handoff 传棒形式** | 干净交棒、迫判断写明白 | 降为「按阶段推进，每阶段落 state」，弱化人格化传棒 |
| **九骨（除价值验证骨、验收骨）** | 女娲自审的尺子 | 降为「价值验证骨 + 验收骨必过，其余参考」——因其余六骨是通用 skill 工艺，非工厂的区分性承重 |
| **三层 turn 校验** | 拦「停下来问用户」 | 降为「开始时校验一次 handoff 合法」，弱化 turn 内／结束两道 |
| **收敛三方共判** | 制衡女娲独断 | 降为「十殿攻净 + 哪吒判净」（女娲自审并入十殿攻），弱化仪式 |

机械机制不是废的——它们让承重机制跑得更稳、更可追溯。但它们不是「删了就全局塌」的骨头。资源紧张时先降它们，保承重的。

## 可降级（锦上添花，第一个砍）

| 机制 | 为什么可砍 |
|------|-----------|
| **各 references 的补充说明** | 参考性内容。核心契约在 SKILL.md + personas，references 是展开 |

## 用法

- 改任何机制前，先查它在这张图谱的位置。承重的改动，要三思（动了全局）；机械的改动，放手（局部）。
- self-bootstrap 跑通过程中暴露的空转机制，若修不到能跑：**承重机制** → 记为 `runtime_blocked`（说明阻断根因），不许降级（红线 9）；**机械机制** → 可降级（标到这里 + 对应文件注明降级形态），因机械不触碰承重点。
- self-bootstrap 跑通过程中若发现某机制被证伪为承重（如意象词库：产物全表格化、丢失「火种」式隐喻，证伪了「压缩工具可降级」的初始判断），更新本图谱把它从可降级挪到承重，并在 deletion test 理由里记录证伪证据（反例产物 + 退化路径）。证伪留痕是工厂修正自己承重判断的方式——「可降级」是假设，反例是裁判。
- 这张图谱本身会演化——每次工厂发现「原来这个机制不承重」，更新它。演化留痕，是工厂学习自己的承重结构的方式。
