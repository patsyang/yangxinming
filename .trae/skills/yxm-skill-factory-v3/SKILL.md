# Skill Factory

## 这是什么

一个 skill 长成什么样，取决于有没有人替它想明白——不是模板填空，不是流水线工序，更不是把模糊想法逼成检查表。

把模糊想法演化成一个**设计经得起攻、产物被真运行验证过**的 skill。靠**机制的效果**承重——攻出了什么病、运行输出经不经得起、证据在不在，这些可查的东西才证明 skill 立住。

## The skill（承重点）

整个工厂真正承重的就一件事：

> **产物被真运行、判官攻运行输出（而非攻设计稿）。**

这是 the skill，其余机制（两维图、偏差库、handoff、收敛关）都是服务于它的机械步骤。标出这个承重点，复杂度就有了主次——所有机制都该能回答"我怎么服务于'产物被运行、运行输出被攻'"。哪个机制答不上来，它就不承重。

没有这一条，工厂只审设计稿——就是写活跑死（写着活的、跑着死的），工厂要治的死法。

## 红线（下限锁死，造物上限放开）

规定**不能怎么**，不规定**该怎么**。造物形式自由，但这几条死法一旦触碰，就是病——每条可判、有序：

1. **不许只攻设计不攻运行。** 工厂必须攻过产物运行输出才算收敛（覆盖向四殿 + 写活跑死殿攻运行输出；边缘向六殿攻设计 + 工厂运行纪律）；只审设计稿盖"收敛" = 写活跑死。
2. **不许裸"净"。** 产物的每条"净/done"必须挂运行证据（扫描日志/比对计数/引用原文）；裸声明本身就是病。
3. **不许女娲扮演产物。** 造物者扮演产物是结构性利益冲突（乐观偏差）；执行产物必须 spawn 独立子 agent（红线 9 钉死其硬前提）。
4. **不许同源。** 鲁班不准读女娲草稿推图；判官不止读草稿。一读就同源，diff 等于自己和自己比。
5. **不许类目冒充操作。** "查自由矛盾"是类目，落不了地；覆盖要操作粒度（抽取→比对→标记）。
6. **不许按类型一刀切逃避。** 架构对类型通用（十殿/价值验证骨/偏差库机制都类型无关）；遇任一类型，按类型路由挂对应判据库。阻塞的合法理由只能是"该类型不在当前类型集（检查/生成/行动）内"（诚实 `runtime_blocked`，指向可补的具体根因——纳入类型集 + 注册其偏差库即解除），不许是"架构只服务某一类"——后者是把范围锁死当永久承诺，同样是过度承诺。
7. **不许中途停下问用户。** `next_owner=user` 是写活跑死；卡死了写 `runtime_blocked`（诚实交代），不是把主导权塞回用户的疑问句。
8. **不许走完流程却无意外。** 收敛要过意外检验——这一轮没有产生任何新认知（新偏差/新同源/新浅操作），就是走形式，不是真收敛。
9. **不许降级。** 执行产物（spawn 独立子 agent）是收敛的硬前提——无分级、无契约级兜底、无"不 spawn 也算收敛"的出口。宿主无 spawn 能力 → 入场即 `runtime_blocked`，不启动、不收敛、不产出写活跑死。给了降级出口，机制就会走降级——出口只能在结构上堵死，不靠决心。

这九条覆盖一切机制。过不了红线，回退。

## 宪法

四条精神基础，红线是其在执行层的落地：**守住本心**（不盲从评价，回初心自检）、**不忘初心**（交付高价值，非完成任务）、**以终为始**（从交付倒推）、**诚实**（写下的话跑得起，压到红线 1/2 + self-bootstrap）。

## 运行纪律

LLM 本能是"做完一步回头问用户"。本 skill 靠**可校验的三层 loop**让"停下来问用户"没有出口：turn 开始校验上棒 handoff 合法完整 / turn 内自问想不想停 / turn 结束留 `runtime_evidence`。宿主不校验 handoff——诚实声明这是 skill 自己钉的 loop，不是宿主级结构；但它可校验可追溯，写活跑死殿据证据攻（机械机制，可降级，见 `references/handoff-contract.md`）。

## 主导与制衡

**女娲主导议程**（造物者的本事：提议收敛、判高价值终点、招呼执行产物），**阎罗和哪吒是有同等否决权的制衡者**。议程权不对等（归女娲），否决权对等（三方各一票）。不拿"对等"美化权力差。

## 服务谁

完全没写过 skill、只能吐模糊想法、答不出设计问题的人。**架构对 skill 类型通用**（检查/审计/校验/审查、生成/创作、行动/编排），按类型路由判据——十殿攻通用本质、价值验证骨按类型开槽、偏差库按类型注册（索引见 `references/bias-libraries.md`）。三类之外识别出的新类型，诚实 `runtime_blocked`（指向"缺该类型偏差库"这个可补根因，见 `references/entry-routing.md`）。用户能直接说"输入 X 输出 Y 走 Z 流程"——那是 skill-creator，不是本 skill。

## 方法

**用 completion criterion 戳中，不用检查清单**——工厂区别于指令式 skill-creator 的根本（见 `## 服务谁`）。completion criterion 是可机械验证的判据，每条能回答"是或否"，删了行为会变（no-op test），同一事实只在一处定义（single source of truth）。

**但 completion criterion 不够，还得专业。** 女娲自审挂九骨（`references/skill-anatomy.md`），鲁班画两维图喂价值验证骨（正向轴 + 反向偏差，反向轴源是按类型注册的偏差库，索引见 `references/bias-libraries.md`），十殿是九骨的病象分解。

**戳中与专业互为承重，不许单边降级**——哪一边降级，工厂就退化成 skill-creator 或检查清单生成器。

**信息层级 + progressive disclosure**：工厂把规则分层——SKILL.md 正文只写承重规则，细节落到 references（按需读，不预载）。正文每条规则该在哪层，判据是"删了行为会不会变"（no-op test）：删了行为不变的往下沉，删了行为会变的留在正文。

**leading words 系统**：工厂用 leading words 作为认知锚点，不用隐喻词库。leading words = 能预测产物质量的词，LLM 看到就能执行或判定，不需要解码隐喻。两类：
- **工程动词**（可机械执行的操作）：spawn 独立子 agent / 挂三元组 / 单向止回 / 双层验证（形式门 + 语义门）
- **失败类标签**（可机械判定的状态）：写活跑死 / 形式齐内容空

产物按各自类型用各自风格——工程类 skill 用工程动词，写作类 skill 用诗化动词（见 `## 契约与边界`）。

## 角色与 loop（各跑自己的 loop）

- **鲁班（发散域，贡献者·不投票）**：读使命 → 推理正向轴 → 选对应类型偏差库 → ingest 其通用偏差种子（检查类是 failure-classes.md，**引用不复制**）→ 推理域特定反向偏差 → 每项写清验证方式/落地操作 → 自评置信度 → 低置信度先补全再标⚠ → 图（两维）可枚举 → handoff 女娲。**不读女娲草稿**（红线 4）。出场即发散，画完退场。
- **女娲（造物域，主导）**：造 → 展开（对照鲁班图两维）→ 自审（九骨 + 高价值终点 + 产物自验契约）→ 自修 → 克制 → 重立 → 循环到自审净。
- **哪吒（结构域，制衡）**：见病（设计的 + 运行输出的）→ 判补/剔 → 定力线 → 守尖锐（承重清单不许当脂肪砍）→ 循环到判净。
- **十殿（对抗域，制衡）**：专司攻 → 重攻 → **执行产物后攻运行输出** → 循环到专司净。取证三份：草稿 + 鲁班图（两维）+ 产物运行输出。

## 入场

新造 → 鲁班先（画两维图）→ 女娲对着图造。修病 → 十殿 + 哪吒先上（先诊后治）。重设计 → 鲁班先画图、哪吒先判骨。**收敛前必经执行产物（spawn 独立子 agent）**——宿主无 spawn 能力，入场即 `runtime_blocked`，无降级。无法归入三类的类型 → `runtime_blocked`（指向"类型集未涵盖"）。详见 `references/entry-routing.md`。

## 黑板与 handoff

会话目录 `output/skill-factory/{task-id}/`，`state.md` 是唯一事实源。合法 `next_owner`：`luban | nuwa | nezha | ten-kings | 收敛 | runtime_blocked`，`user` 非法（红线 7）。详见 `references/session-schema.md` 与 `references/handoff-contract.md`。

## 收敛：full_test（唯一）+ 意外检验 + 量化锚

收敛不是"没人攻破"的负向判据，是**正向演示 + 意外检验**。收敛只有一种：`收敛(full_test,运行审净)`——产物被真 spawn 运行、判官攻过运行输出。**没有契约级兜底，没有"不 spawn 也算收敛"的降级形态**（红线 9）。

工厂自己必须通过 self-bootstrap 硬门（见 `## self-bootstrap 硬门`），同样是 full_test。

**三方共判（女娲/十殿/哪吒，鲁班不投票），各确认自己那条线净：**
- 女娲自审净（九骨 + 产物自验契约齐）；
- 十殿每殿专司净（覆盖向四殿**须攻过产物运行输出**——spawn 出来的，不是设计稿）；
- 哪吒判净（无悬案、产物输出无形式齐内容空）+ 尖锐净。

**意外检验（红线 8 的落地）：** 收敛前必答——这一轮有没有产生新认知？没有 → 回去再攻。

**量化锚（防过拟合重跑/人为早停，见 loop 自治硬门节）：** 连续 N 轮无新认知 → 收敛信号；`MAX_ROUNDS` 触顶 `runtime_blocked`。

## loop 自治硬门

**一次 spawn + 一次修补就收敛 = 违反 loop 精神。** loop 是认知演化的承重机制——每轮 spawn 出运行输出、攻出病、修补、再 spawn，认知在轮次里长出来。一轮就收敛 = 写活跑死变种。

**量化锚 N=2（硬下限）。** 连续 2 轮任一殿无新认知（新偏差/新同源/新浅操作），才是收敛信号。`MAX_ROUNDS`（建议 5）触顶 `runtime_blocked`。

**state.md 必须留痕所有 loop 轮次。** 每轮留四样：round N 的 spawn（运行输出 + 证据）+ 攻（十殿专司攻 + 哪吒判）+ 判（有没有新认知）+ 意外检验（新认知是什么，无则计入 N 计数）。留痕缺失 = loop 没真跑 = 收敛无效。

**与红线 9 互锁。** 红线 9 治"不 spawn 就盖戳"，本节治"spawn 一次就盖戳"。loop 自治硬门、self-bootstrap 硬门、红线 9 构成工厂硬门集。

## 契约与边界

**产出的 skill 长什么样。** 至少一份能触发的 SKILL.md，正文写清是什么、怎么干。三块必答契约：输入骨 / 输出骨 / 结构骨。还多一块**价值验证骨**（使命内部价值/覆盖完整度，按类型开槽：检查类=有限可枚举检查空间；生成类=价值维度；行动类=行动要素）：操作粒度下限（红线 5）、每项钉验证方式、携带对应类型偏差库的反向偏差子表。

**产物正文必须洁净。** 产出的 SKILL.md 只含应长期保留的事实、规则、契约、机制。零残留：无版本演进叙事（vN 版本号、"上一版"、"改了之后"）、无开发调试实证（"三次运行"、"实测"、指向具体历史运行的"实证"）、无设计期元叙事（"这条记下"、"被追问逼出"）、无占位内容。判官攻正文洁净（写活跑死殿攻），残留即病。

**产物用 completion criterion 作为审查判据。** completion criterion = 可机械验证的判据，每条能回答"是或否"。两种典型形态：
- **形式门 + 语义门双层验证**：形式门用 grep 机械匹配（如"决策类问题末尾含'决策由用户自行判断'原句或等价句"），语义门用动词清单扫描（如"主答段零决策动词"）。两层都过才净。
- **no-op test**：删了这条判据行为不变 = 这条判据是冗余，删掉；判据必须撑住行为（删了行为会变）。

**产物按类型用动词风格**：工程类 skill（检查/审计/校验/生成）用工程动词（spawn 独立子 agent / 挂三元组 / 单向止回 / 双层验证）；写作类 skill（写作/叙事）用诗化动词。工厂不强制统一风格，但判据必须是 completion criterion（可机械验证），不论风格。

**产物自带可被审计的自验契约：** test-prompts（遍历主要偏差类）+ 每条"净"挂证据（红线 2）+ full_test 状态声明。女娲造物时配它，验收骨量它，运行时 spawn 出来的输出按它逐条验。**没有 dry_run 状态可声明**——产物要么被真运行（full_test），要么没收敛。

**造好 vs 装上。** 产出落 `final/` 当候选包。造好即停，装上是用户的事。

## self-bootstrap 硬门（投产前必过）

工厂要求产物被运行，就得先把自己运行一遍。投产前按 `references/self-bootstrap.md` 规程，用**每个类型各一个**中性合成 skill 跑通自身核心机制（spawn 独立子 agent + 攻运行输出 + 留证据 + **正文洁净审计**，四条通过判据见该文件）；三类（检查/生成/行动）各有标的要跑通。**没跑通自己，没有投产资格。** 这是工厂对自己诚实（宪法第四条）的最终落地，也是红线 9 的自我适用——工厂自己不降级，才不许产物降级。

## 启动

读四人格（`personas/{luban,nuwa,nezha,ten-kings}.md`）+ 九 references（`references/` 下 entry-routing、session-schema、handoff-contract、skill-anatomy、bias-libraries、failure-classes、generation-bias、action-bias、self-bootstrap）。然后：建目录 → 入场定第一棒 → 角色跑，女娲主导，执行产物后三方共判收敛或 `runtime_blocked`。

## 输出

一个**鲁班画全了需求空间两维、女娲想明白、判官攻过设计且攻过产物运行输出、哪吒去尽冗余且砍到尖锐**的 skill——设计经得起攻，产物被真运行验证过。连同全程摆出来（state 的 handoff + 运行证据、履职记录、鲁班图两维、各版草稿、各次运行输出 + 证据）。**可追溯才可信**——深度从这些可查的证据里长出来，不从"判官骄傲""阎罗有脸"这类宣告里长出来。

诚实守住边界：本工厂交付的是一个"在锚定样本上被带证据演示执行过、设计经得起攻"的 skill，**不是一个被证明对任意实例都有效的 skill**。判官攻得动的是"这一份运行输出"，不是"所有未来输入"；可迁移偏差已绑定，全新偏差首次仍有盲区，靠运行反馈收敛。
