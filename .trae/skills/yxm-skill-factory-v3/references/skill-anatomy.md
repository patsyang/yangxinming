# Skill 解剖图

女娲自审的尺子，十殿攻的地图。skill 立得住靠九块骨头都正——光有哲学不够，得真懂 skill 由什么构成。

> 第九块是**价值验证骨**，补前八骨的盲区：八骨只问"怎么干（流程）"，不问"使命声称的价值/覆盖干全了没"。与干活骨正交：干活骨管流程对不对，价值验证骨管使命内部的价值/覆盖全不全。按 skill 类型开槽，三关通用——**可枚举空间**、**操作粒度下限**、**反向偏差子表**。

## 触发骨 · 何时现身、何时沉默
description 是触发器不是自我介绍。立得住：说得出哪种话音该现身、哪种长得像必须忍住，且边界写进 description 本身（宿主读它就能分辨，不必让用户读正文）。病：含糊到什么都认领 / 撞车 / 边界只写在正文。

## 身份骨 · 是什么、不是什么
立得住：能列三件坚决不做的事并说得出为什么。病：只说"做什么"说不清"不做什么"——迟早什么都想做、什么都做不好。

## 干活骨 · 怎么真干
方法是现场一步步怎么干，不是哲学外衣。立得住：照着能复现动作（怎么调子 agent / 读写文件 / 传棒）。病：全是"应该怎样"没有"具体怎么干"。

## 价值验证骨 · 使命声称的价值/覆盖，干全了没（按类型开槽）

这块骨问的是：使命声称要交付的价值（检查类的检查空间、生成类的价值维度、行动类的行动要素），**覆盖全了吗、落得了地吗**。对任一类型都成立——类型只决定"覆盖什么"和"拿什么偏差对照"，不决定这块骨在不在。

**按类型开槽**（覆盖什么由类型定，三关通用）：

| 类型 | 可枚举空间（覆盖什么） | 反向偏差库 |
|---|---|---|
| 检查/审计/校验/审查 | 有限可枚举检查空间（N 条检查项） | `failure-classes.md` |
| 生成/创作 | 价值维度（该交付哪些维度的价值） | `generation-bias.md` |
| 行动/编排 | 行动要素（动作/状态变更的完整要素） | `action-bias.md` |

立得住要过三关（类型无关）：

1. **可枚举空间**——使命被拆成可数清的覆盖空间（"图上有 N 条正向轴 / N 个价值维度 / N 个行动要素"），不是散文。
2. **操作粒度下限（治类目冒充）**——"可枚举"是**操作级**（item），不是**类目级**（category）。"查自由矛盾"是类目，落不了地；"抽取所有同类数值，两两比对，标记不等对"是操作，能跑。一条价值/检查必须钉死**怎么验（搜索词 / 正则 / 脚本 / 逐字比对 / 多源交叉 / 工具调用 / 生成类的可判据维度 / 行动类的可观测状态）**到一个具体动作。
3. **反向偏差子表（治未知偏差）**——光有正向轴不够，还得有**反向偏差（会出什么毛病）**，每类钉死落地操作。参照是鲁班图反向偏差（`luban.md`）+ 该类型偏差库通用种子（索引见 `bias-libraries.md`）。女娲逐条说清"覆盖了/显式不做并写了理由"。

病：干活骨写了"逐条对照"却说不清一共几条、每条怎么验——这是流程不是覆盖；类目级冒充操作级（"查自由矛盾"当一条检查项 / "要有洞察"当一条价值维度）；图上的轴 / 偏差被无声略过（既没做也没安置）；**判官脑子里有的偏差，价值验证骨上却没有**（判官拿某个具体偏差当教材，价值验证骨却没把它绑成覆盖项）。

**价值验证骨是命门**：skill 漏掉一整类该交付的价值/覆盖，根往往在这块骨不存在或停在类目粒度——女娲自审尺子上没有它，十殿也不攻它。

## 输入骨 · 用户怎么喂料
立得住：用户读完知道怎么喂——粘贴还是给路径？什么格式（txt / Word / PDF / Excel）？必需没给齐怎样？可选有什么？前置条件？病：写成"文件路径或内容"这种含糊话。

## 输出骨 · 跑完吐什么、落哪
立得住：用户知道拿到什么、在哪拿——单文件（.md / .html）？对话内容？一组文件？落哪个路径？命名规则（覆盖 / 带时间戳）？病：写"一份报告"没形态没落点，或承诺形态但路径走不通。

## 结构骨 · 自身由什么文件组成
立得住：结构匹配复杂度——该配配套的配，不该配的不凑；配套放什么由 skill 的需要定（参考知识 references / 角色定义 personas / 模板 templates / 示例 examples 都可能）；SKILL.md 写清有哪些配套、各自干嘛、引没引用。病：全塞 SKILL.md（又长又乱）/ 凑数配套 / 有配套没引用（断桥）。

## 交付骨 · 用户拿到什么高价值（价值层，形态归上面三骨）
交付物不是流程副产品，是让用户世界真变一点的东西。立得住：和高价值终点对得上，比"完整但平庸"更锋利；造好和装上分得清。病：交付流程痕迹不是价值；造好装上混一团。

## 验收骨 · 怎么知道好了（绑到产物运行）
立得住：有能判是或否的判据，且**有运行证据可查**——产物的每条结论（"净/done/clean/无异常"）必须挂运行证据（扫描日志/比对计数/引用原文）；裸声明本身就是病（红线 2）。

产物自验契约（test-prompts/证据字段/偏差子表）是女娲造物时配在产物里的，让运行输出可被审计。运行时 spawn 子 agent 跑产物，判官对照这份契约攻运行输出——它不是独立的收敛路径（红线 9），是产物自带的可审计性，运行时被验。

病：全凭主观没法复核；**只审设计不审运行**（验收骨名实不符，写着"运行证据可查"，运行的却只有工厂自己的 handoff，产物从没被运行）；产物的"净"不带证据（行尸殿攻、哪吒剔石膏）。

## 与十殿对应
触发骨↔触发殿；身份骨↔边界殿 / 核心殿；干活骨↔核心殿；**价值验证骨↔覆盖殿 / 一致性深度殿 / 严重度殿 / 能力桥殿**；输入骨↔契约殿；输出骨↔契约殿；结构骨↔补丁殿 / 契约殿；交付骨↔核心殿；**验收骨↔行尸殿（行尸殿攻两层运行背叛：工厂自身的 + 产物的）**。

女娲用这图自审能见之病，自己修不等阎罗；十殿攻她看不见的盲点。分工清楚，不重复劳动。价值验证骨这块由鲁班画图（两维）、女娲对着自审、覆盖殿 diff——三方各出一力。验收骨这块由女娲给产物配自验契约、行尸殿攻产物运行背叛——两端各出一力。
